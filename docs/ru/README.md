# Base de recherche utilisateur (RU)

## En clair

Ici on range les **enseignements** issus de la recherche utilisateur (entretiens,
observations, retours Design / Accessibilité) pour que les agents et l’équipe
produit s’y réfèrent **avant** de trancher un parcours.

Ce n’est **pas** la doc fonctionnelle des écrans (`docs/fonctionnel/`) : c’est le
*pourquoi* métier, pas le *comment* actuel du widget.

## Public

| Lecteur | Usage |
|---------|--------|
| Responsable Design | Ancrer les parcours dans des faits d’usage |
| Responsable Accessibilité | Rappeler les contraintes d’usage pour toutes et tous |
| Agents / contributeurs | Lire avant conception ; proposer une fiche si insight manquant |

## Comment ajouter un insight

1. Copier [`_TEMPLATE.md`](_TEMPLATE.md) → `insights/YYYY-MM-sujet-court.md`
2. Remplir sans noms / e-mails / montants nominatifs (dépôt public)
3. Ajouter une ligne au tableau ci-dessous
4. Si le sujet est lié à une carte kanban / issue : noter le lien

## Règles

- Une fiche = **un** sujet borné.
- Distinguer **fait observé**, **hypothèse**, **décision ouverte**.
- Compléter après relecture Design / Accessibilité (ne pas figer trop tôt).
